# OpenPI 独立验证集离线评估

入口：`scripts/evaluate_g1_openpi.py`。它仅加载模型并前向计算，不创建优化器、不反向传播、不连接机器人。固定上游 OpenPI 提交 `981483dca0fd9acba698fea00aa6e52d56a66c58`，使用本次冻结视觉编码器的双 LoRA Pi05 配置。

## 数据和比较对象

- 验证清单为 `data/batch_20261005/manifest_validation.json`，12 条示范，每任务 4 条，24 FPS。
- 检查清单 SHA256、训练/验证路径分离、动作字段名称和顺序、相机与任务提示、开发版数据质量证据。
- 使用检查点内 `assets/g1_buttons/norm_stats.json`；与训练工件中的 SHA256 匹配，不计算验证统计。
- 训练前基线：完整官方 Pi05 基础权重，LoRA 使用同一训练 seed 42 和上游两次 RNG split 初始化。A/B 都是正态随机初始化，不是零。
- 训练后模型：本次 100 步的完整检查点。恢复两者时保留训练的混合数据类型，冻结主干为 bfloat16、可训练部分为 float32，避免额外量化影响比较。
- 两个模型在独立进程中先后加载，使用同一评估计划、噪声种子、窗口与动作采样步数。计算开始后若评估源码变化，后续进程拒绝启动。

## 窗口与随机性

损失默认覆盖每条示范所有完整 24 步窗口，不跨 episode，也不再次移动已有 `action[t]` 下一采样状态标签。12 条验证示范共 3,702 个唯一窗口：press 989、rotate 1,626、toggle 1,087。

动作预测默认每 24 帧取一个完整窗口，再补最后一个窗口并去重。用 `--action-stride 1` 可以对全部窗口预测，但计算量会增加。相邻窗口重叠，报告不能将它们当作独立实验。

默认随机种子为 0、1、2。每条示范和窗口由稳定 SHA256 映射派生 RNG，损失与动作采样使用不同命名空间。两个模型对同一窗口使用相同噪声；不挑选三个种子中最好的结果。

默认 `--loss-seed-batch 1` 按种子逐次调用官方损失函数。可选值 3 将三次独立损失计算向量化，但会增加内存占用，且本机小样本实测更慢，因此本次完整评估使用默认值 1。改变批处理方式后，应重新运行两模型的完整比较。

## 指标

| 指标 | 定义 |
|---|---|
| `flow_loss_32` | 官方 `compute_loss(..., train=False)`；关闭图像增强，包含全部 32 维及 14 个补零维度，平均 24 个时间步与固定种子 |
| `normalized_action_mse_18` | 采样动作相对于示范的归一化 MSE，仅真实 18 维 |
| `position_mm_*` | 反归一化后，双臂分别计算三维位置欧氏距离，以 mm 表示；另保留左右臂指标 |
| `orientation_deg_*` | xyzw 四元数归一化后的 SO(3) 最短旋转角误差；`q` 与 `-q` 等价 |
| `gripper_mae_*` | 四个原始归一化夹爪控制通道的绝对误差；预测不裁剪 |
| `quaternion_invalid_fraction` | 预测四元数范数小于 `1e-8` 的比例；这些预测同时记 180° 误差，非法示范四元数直接拒绝 |
| `quaternion_norm_mae` | 原始预测四元数范数相对 1 的偏差 |
| `gripper_out_of_range_fraction` | 原始预测夹爪控制值超出 `[0,1]` 的比例 |

动作字段按数据元数据检查：左位置 0:3、左四元数 3:7、右位置 7:10、右四元数 10:14、四夹爪 14:18。报告第一步、前 6 步和完整 24 步误差。模型补零的 14 维不计入采样动作指标。

同时计算“保持当前状态”的姿态/夹爪预测参照，用于识别静止轨迹造成的低误差。它不提供模型损失，也不代表能完成任务。

每条示范先平均固定种子和窗口，然后任务内示范等权平均，最后三任务等权汇总。报告保留逐示范配对差值，避免长轨迹占据更大权重；当前每任务仅 4 条验证示范，不能据此宣称跨场景泛化。

## 在现有 WSL 中运行

以下均为 Linux Bash。使用一个新输出目录，脚本拒绝覆盖已有评估。

```bash
cd ~/g1-wsl-20261007/project
export OPENPI_DATA_HOME="$HOME/g1-wsl-20261007/model-cache"
export XLA_PYTHON_CLIENT_PREALLOCATE=false
export OMP_NUM_THREADS=1
../openpi/.venv/bin/python scripts/evaluate_g1_openpi.py \
  --openpi-root ../openpi \
  --dataset data/batch_20261005/manifest_validation.json \
  --checkpoint data/wsl_finetune_20261007/checkpoints/pi05_g1_multitask_lora_frozen_vision/g1_multitask_frozen_vision_100_v1/99 \
  --image-cache data/wsl_finetune_20261007/image_cache \
  --output data/offline_eval_new_run \
  --seeds 0 1 2 --loss-seed-batch 1
```

`model_config.json` 默认从实验目录读取；迁移时保留它，可通过 `--model-config` 指定。数据路径以清单位置解析。需要训练清单用于泄漏检查，默认在验证清单旁读取 `manifest_train.json`。模型缓存与原训练使用同一路径，避免重新下载权重。

默认 `--variant compare` 顺序评估两个模型；可用 `--variant baseline` 或 `--variant finetuned` 单独排障。`--smoke` 只运行第一条示范的两个窗口，报告会标记，它不构成完整验证。

## 结果含义

更低的独立验证损失与动作误差，表示模型在未参与训练的记录观测上更接近示范。它们不等同于正确按钮识别率，也不等同于真实闭环成功率。现有验证示范与训练示范共享柜体和场景，主要变化为接近路点与动作时长。

后续需将模型动作接入仿真，重新获取观测，并结合目标解析和成功判定器统计操作成功率、误操作、超时等；不能把离线动作直接当作电机角度发送。

本次被评估的 100 步训练使用上游默认 1,000 步学习率预热，峰值 `2.5e-5`；第 0/99 步学习率约为 `2.50e-8` / `2.50e-6`。它仍是预热内的短程实验。这个事实可以帮助解释改善幅度，不能替代实际验证指标，也不保证增加步数后一定更好。

## 2026-10-07 完整实测

本机 WSL Ubuntu 26.04 / RTX 5080 已完成默认配对评估，输出为 `data/offline_eval_20261007_v1/`。两个模型各覆盖 12 条示范、3,702 个唯一损失窗口、174 个唯一动作窗口；每窗口使用 3 个固定种子，分别得到 11,106 次损失评估和 522 个预测动作段。完整覆盖、两模型标签/帧号/种子一致、训练前 LoRA 初始化一致及全部 CSV 指标/预测有限性检查通过，记录于 `verification.json`。

|---|---:|---:|---:|---:|
| press | 0.164792 → 0.152018 | 51.690 → 49.859 | 14.472 → 14.598 | 0.206175 → 0.204093 |
| rotate | 0.196365 → 0.180333 | 67.627 → 64.860 | 21.801 → 21.495 | 0.255841 → 0.252320 |

以上动作指标均为完整 24 步窗口平均。宏平均损失改善约 7.4%，位置改善约 4.1%；按压任务姿态略有退化。双臂平均会被几乎静止的左臂稀释，因此还应看操作右臂和朴素参照：

|---|---:|---:|---:|
| 右臂位置误差 mm | 110.599 | 105.924 | 41.870 |
| 右臂姿态误差 ° | 31.124 | 30.601 | 8.455 |

微调后第一步/前 6 步双臂位置误差分别为 `33.840 / 38.128 mm`。原始输出四元数范数 MAE 为 `0.096034`，未出现零范数四元数；夹爪越界比例为 `0.1713%`。评估没有裁剪这些输出；闭环控制需要明确记录四元数归一化和动作约束，不能以控制后的指标替换原始模型误差。

全程约 35.4 分钟，两模型顺序加载；微调模型每次生成 24 步动作的平均耗时约 100.6 ms，首次损失/动作编译分别约 14.8 / 7.2 秒。每 2 秒采样的整卡显存峰值为 10,442 MiB（包含桌面）；进程组 RSS 峰值约 10.07 GiB，可能重复计算共享页；主机交换内存峰值约 141.8 MiB。资源记录位于 `data/offline_eval_prep_20261007/`。这次推理耗时不包含 Windows 摄像头获取、网络传输或机器人执行，不能当作闭环速度。

100 步训练仍处在 1,000 步预热的前 10%，第 99 步学习率约为峰值的 10%。这解释了本次训练规模较小，却不能证明误差仅由预热造成。保持当前状态参照明显优于当前模型，也不能说明静止即可成功：它只是揭示记录轨迹中连续、缓慢或静止片段占比以及模型预测不足。当前结论是训练后拟合有限改善，尚未证明自主识别或操作能力。
