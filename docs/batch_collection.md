# 批量示范采集与自动质量筛选

入口为 `scripts/batch_collect.py`，使用既有官方采集包装器和开发版关节成功判定器。默认三类任务各保留 20 条通过示范，24 FPS，两路 1280×960 视频，18 维状态与动作，LeRobot v2.1 格式。

## 运行

先在 OrcaLab 打开工作区 `OrcaLab布局/g1_pick_buttons.json`，进入运行模式，并选择“无仿真程序（手动启动）”。不要同时运行其他控制器。仅端口开放不代表布局已进入运行模式。

在项目根目录使用 PowerShell：

```powershell
python scripts/batch_collect.py --output data/batch_20261005
```

已有批次续跑：

```powershell
python scripts/batch_collect.py --output data/batch_20261005 --resume
```

新批次必须用新目录。`--per-task` 和 `--seed` 只在创建计划时生效；续跑使用被冻结的 `plan.json`。`--plan-only` 只生成计划；`--max-new 3` 可用于三条试采。批次目录内创建 `STOP` 文件后，当前示范完成即停止；续跑前移除该文件。

每条示范采用独立进程。`.running.lock` 防止同一批次重复启动；异常终止遗留锁时，先确认记录的进程已结束且无采集子进程，再手动移除锁。中断的示范保留但不收录。连续三次失败自动停止；先查日志修复问题，再续跑。默认每类最多尝试 25 次，不会无限重试。

## 变化范围

- 初始自由空间接近路点偏移：x/y ±8 mm、z ±6 mm。
- 各段时长统一缩放至 0.92–1.08 倍，接触路点保持不变。
- 旋钮使用已修正的撤离轨迹 `configs/waypoint_rotate_clearance.yaml`。
- 不随机移动柜体、机器人基座或光源。验证集衡量同场景轨迹变化，不能据此声称新场景泛化。

## 筛选

完整解码两路视频，核验帧数、分辨率、24 FPS、18 维有限状态/动作、时间戳、单位四元数、夹爪范围，以及 `action[t] = state[t+1]`。任务文本必须与采集任务一致。解码图像唯一比例至少 50%，并检查轨迹位置/旋转跳变。

物理审计检查所有控制步数值有限；以场景目标关节判定按钮按压释放、旋钮或拨杆定向转动；监测非目标关节超过阈值的变化。检查审计记录与视频帧数及末尾时间的粗略一致性。未知、缺失或异常证据均不收录。

这是**开发版代理判定**，不是官方裁判。它不证明精确相机/物理帧同步，也未完整检测碰撞归因、摔倒、抖动与撤离。唯一图像比例不能替代对模糊、遮挡的视觉质量评估。官方 `joint_strip on / strip_col off` 配置也不代表比赛完整碰撞条件。

## 输出与训练接口

- `summary.json`：数量、状态及逐条原因。
- `manifest_train.json` / `manifest_validation.json`：默认每类 16/4 条，按整条示范划分。
- `manifest_all.json`：全部通过示范，不能用它统计训练归一化后再报告独立验证指标。
- `attempts/<编号>_<任务>/`：原始数据、采集日志、轨迹、种子、物理审计、质量判定、图像联系表。
- `inputs/`：冻结任务、场景配置、路点和判定阈值；SHA-256 记录于计划中。

OpenPI 的现有 `load_g1_dataset` 已支持同一任务多条独立数据源，并按任务均衡采样。将训练入口的 `--dataset` 指向训练清单；验证清单独立使用，归一化统计仅来自训练集。当前解码器将压缩至 224×224 的图像放入内存，扩大数据量前应改为有界缓存。

本步骤只生成和筛选示范，不训练模型，也不代表模型已学会自主操作。

完成后可执行 `python scripts/verify_batch.py data/batch_20261005`，生成 `batch_verification.json`：检查全部通过记录的任务标签、质量证据、审计哈希、种子及训练/验证分离，并从每个任务、每个划分各解码一条真实示范，验证 OpenPI 输入转换。此复核不执行训练。
