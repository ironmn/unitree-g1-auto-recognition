# Windows OrcaLab 模型闭环评估

`scripts/test_g1_openpi_orcalab.py` 将 WSL 的 Pi05 模型接入 Windows 官方右臂 OSC，执行模型预测并保存可审计结果。它使用当前相机和机器人反馈重新规划；不会播放示范轨迹，也不会读取未来示范状态。

## 1. 两个独立环境

- WSL：使用已验证的 OpenPI 环境和训练检查点启动 `scripts/serve_g1_openpi.py`，模型服务监听 `127.0.0.1:8766`。完整模型加载配置由服务参数决定，`/health` 信息会写入评估报告。
- Windows：使用已有官方采集解释器（或按官方 Windows 指南安装好的等价环境），要求 Python 3.12、OrcaGym 26.8.2 以及官方控制器依赖。无需在 Windows 安装 OpenPI/JAX。
- 仿真：打开 `binjiang_competition_2026`，加载用户保存的 `OrcaLab布局/g1_pick_buttons.json`，以“无仿真程序（手动启动）”进入 Runtime。gRPC 为 `localhost:50051`；启用头部/右腕 RGB、NVENC，颜色端口分别为 7090、7080。不要同时运行其他控制程序。

本机桌面启动入口是 Conda `orcalab` 环境的 `Scripts/orcalab.exe`。迁移电脑时请使用实际安装环境的路径。

在已完成本机离线评估的 WSL 项目目录启动同一检查点：

```bash
cd ~/g1-wsl-20261007/project
export OPENPI_DATA_HOME="$HOME/g1-wsl-20261007/model-cache"
export XLA_PYTHON_CLIENT_PREALLOCATE=false
export OMP_NUM_THREADS=1
../openpi/.venv/bin/python scripts/serve_g1_openpi.py \
  --openpi-root ../openpi \
  --plan data/offline_eval_20261007_v1/plan.json \
  --port 8766 --sampling-steps 10
```

迁移时，先在新环境重新生成离线评估 `plan.json`，其中的检查点绝对路径、模型配置和统计哈希必须对应实际文件。服务会检查固定 OpenPI 版本、检查点完整性和归一化哈希；支持本次已评估的冻结视觉编码器配置。

## 2. 预检与执行

在仓库根目录执行。未传 `--execute` 的预检只查询模型服务和 TCP 连通性，不创建、重置或步进仿真环境：

```powershell
$collectionPython = Join-Path $env:USERPROFILE '.codex\runtimes\g1-collection\Scripts\python.exe'
& $collectionPython scripts/test_g1_openpi_orcalab.py
```

完成预检且 GUI 已进入 Runtime 后，运行每类一次、30 秒仿真时间的首轮测试：

```powershell
& $collectionPython scripts/test_g1_openpi_orcalab.py `
  --execute --tasks press,rotate,toggle --repeats 1 `
  --seconds 30 --fps 24 --execute-horizon 6 `
  --seed 20261007 --output data/orcalab_model_eval_20261007
```

输出目录必须不存在，避免覆盖之前的证据。`--official-root` 可以指定官方代码包目录，默认使用相邻 `Binjiang_Competition`。需要更小闭环执行窗口时可设 `--execute-horizon 4`。使用不同模型时应指定不同输出目录，并保持任务、初始状态、噪声种子和控制约束一致。

`--execute` 会按每次试验重置机器人和本地仿真状态，采用示范采集时的双臂初始姿态，保持机器人基座和腿部的任务模型配置。每条任务使用训练时原始指令：按压停止按钮、旋转旋钮、拨动拨杆式按钮。场景资产来自 GUI 已加载布局，程序不生成其他场景或目标。

## 3. 动作和同步契约

模型输出为 `(24,18)` 的原始绝对末端位姿/夹爪：

```text
[左 xyz(3), 左 xyzw(4), 右 xyz(3), 右 xyzw(4), 左夹爪(2), 右夹爪(2)]
```

位置以米表示，相对 `torso_link_rev_1_0` 基座；夹爪是执行器量程归一化值。程序仅执行与官方示范一致的右臂和右夹爪。右位置传给 `update_action_position`，右 xyzw 四元数传给 `update_action_axisangle`（该方法名虽为轴角，输入实际为四元数）；官方控制器完成世界坐标转换和 OSC 扭矩计算。右夹爪从 `[0,1]` 反归一化到 `[-1,2]`。18 维向量不能直接当关节角传给 `env.step`。

状态从当前双末端基座位姿及夹爪执行器控制值构造，裁剪模型中缺失的左夹爪控制按采集脚本填 0，归一化后为 1/3。相机接收器按相同 `simulate_index` 匹配头部和右腕，缺失时停止试验，不替换成旧图。帧转 RGB 并按训练适配器的 PIL 双线性缩放/黑边填充得到 224×224 输入，保存为无损 PNG。

物理控制周期为 5 ms，动作按 24 FPS 用 8/9 个控制步调度。每次执行预测的前 6 帧，再查询新观测。相机等待和模型推理期间暂停本地仿真时钟，墙钟耗时与模型采样时间分别记录。因此此模式检验策略闭环行为，还不能证明真实机器人实时控制可用。

## 4. 约束与判定

默认右末端每动作帧的位置增量上限为 20 mm，旋转增量上限为 10°；四元数归一化、夹爪裁剪到 `[0,1]`。超过 0.5 m 的右目标跳变、超出 1.5 m 基座工作半径或无效四元数会结束试验。报告逐帧保存原始动作、实际命令和每项约束影响。成功率对应**带约束的模型控制链**，并非无限制原始模型输出。

复用 `SuccessEvaluator`，在动作前读取场景关节基线，再按 24 FPS 记录目标和非目标关节：

| 任务 | 开发判定 |
|---|---|
| 按压 | 正向位移 ≥1.5 mm，持续 ≥80 ms，随后回到基线 ±0.5 mm |
| 旋钮 | 相对基线负向旋转 ≥15°，持续 ≥80 ms |
| 拨杆 | 相对基线正向旋转 ≥15°，持续 ≥80 ms |

监测其他按钮、旋钮或拨杆是否同时变化。判定保留 `proxy_pass`、`non_target_change`、`incomplete`、`timeout`、`inconclusive` 等状态；30 秒截止由 `stop_reason=time_limit` 标记，开发判定器本身仍保留原配置 180 秒超时。无效物理状态、动作拒绝或接口错误另外记录为执行失败，停止本轮，不无限重试。

按钮的 1.5 mm 行程、方向和保持时间是开发假设，不能代表官方评分。采集时官方 `mj_joint_strip` 调整了交互关节限位/按钮弹簧，并禁用了部分裁剪机器人几何体碰撞；评估匹配这套设置。判定器没有验证撤退、摔倒、碰撞因果归属或抖动规则，`official_success` 始终为空。

## 5. 结果文件

- `report.json`：模型服务信息、配置、代码哈希、试验汇总、开发代理成功数和限制。
- 每任务 `result.json`：目标、任务指令、噪声种子、结束原因、推理耗时、约束次数和成功判定事件。
- `trajectory.jsonl`：实际状态、场景关节、接触数、原始模型输出、实际命令和跟踪误差。
- `prediction_*.npz`：每次重规划的原始 24 帧输出、输入状态、观测帧号和噪声种子，不使用 pickle。
- `frames/*_head.png` / `*_wrist_r.png`：每次模型调用对应的真实相机输入。

第一轮每任务只有一次，只能说明这三个具体试验的行为。必须结合误触、轨迹、约束比例、推理延迟和终止原因分析；不能把少量代理通过当成模型已经泛化或达到比赛成功率。下一轮应固定多个初始姿态/目标条件，并分别评估基础模型与微调模型。

纯离线测试可运行：`python -m unittest discover -s tests -p test_policy_client.py -v`。这些测试验证传输和控制边界，不启动 OrcaLab。

## 6. 本机首轮实测（2026-10-07）

使用 WSL 已训练 100 次更新的冻结视觉编码器 Pi05 检查点，采样 10 步，每次执行 6 个预测动作帧。Windows OrcaLab 实际执行每任务一次、30 秒仿真时间，24 FPS，共 2,160 个动作帧和 360 次模型调用；已完成三条测试，无模型执行异常或物理非有限值。

| 任务 | 目标关节最大有向变化 | 开发判定 | 位置增量限幅帧 | 姿态增量限幅帧 |
|---|---:|---|---:|---:|
| 按压停止按钮 | 0 mm | 30 秒截止，未完成 | 187 / 720 | 386 / 720 |
| 旋转旋钮 | 0.050° | 30 秒截止，未达到 15° | 303 / 720 | 558 / 720 |
| 拨动拨杆 | 12.106° | 30 秒截止，未达到 15° | 260 / 720 | 569 / 720 |

首轮代理成功为 **0 / 3**。非目标监测关节均未超过开发阈值。所有执行帧的原始右姿态四元数都需要归一化；较高的姿态限幅比例说明原始输出与当前反馈仍有明显差异。这一检查点已经可以完成推理和控制链调用，但还不能可靠完成三类目标操作。

随后增加一次 **30 秒静止保持对照**：右末端保持重置后的实际位姿、右夹爪保持打开，不调用模型、不播放示范。对照初始 18 维状态及全部场景关节基线与模型试验完全相同。按相同 24 FPS 比较三个模型试验各 720 帧的八个场景关节，全部曲线与静止对照的逐帧差都为 **0.0**；对照中的旋钮/拨杆同样变化约 0.050° / 12.106°。因此上表的角度变化是场景被动漂移证据，**不能当成模型操作进展**；三个模型试验均没有产生区别于静止对照的目标关节变化。

对照原始轨迹、起止相机输入、执行脚本哈希和比较结果保存在 `data/orcalab_hold_reference_20261007_v1/`；本机执行脚本为 `data/orcalab_eval_prep_20261007/run_hold_reference.py`，无模型请求，未改场景或控制器源代码。这个对照也说明单靠关节位移代理缺少因果归属，后续成功测试应加入静止对照或相应漂移标定。

模型采样均值分别约 839 / 654 / 650 ms，其中按压首请求包含约 22.7 秒 JIT 编译；后两项已预热。每次只执行 0.25 秒仿真动作，当前服务在真实连续时间下无法按该周期及时补充动作。此轮通过暂停仿真时间进行离线节奏的闭环测试，不能视为实时部署通过。

本机证据保存在 `data/orcalab_model_eval_20261007_v3/`，源代码契约复核保存在 `data/orcalab_eval_prep_20261007/state_contract_review.json`。首次模型输入与采集首帧的右末端位置差小于 0.003 mm，夹爪值完全相同，排除了初始 18 维状态字段/单位/四元数顺序接错这一解释。此前两轮联调只在初始化阶段失败，没有执行模型动作，未计入三个策略试验。
